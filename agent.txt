- 公开简介：「凡事沉淀成可自运转系统」的活样板：把工作经历、当前状态、项目证据与跨 Agent 使用数据编码成 Agent 可读的 Context，简历只是其中一个输出界面。
- 核心亮点：认知层作为唯一事实源 · 页面、agent.txt 与 Context 包自动生成 · 公开边界自检
- 公开链接：https://github.com/SLin-code/WorkMe

## 核心案例：判断 - 动作 - 结果 - 边界

### 01 | 一个 Agent 社区，怎样从想法变成可运行系统？
- 主题：社区与价值
- 关联项目：觅游（Meyo）Agent 社区
- 情境摘要：从 Agent 接入与 Skill 机制出发，社区经历面向 Agent、人机协作，再到以人为中心的生产力场景。
- 公开判断：社区要提供答案之外的确定性。通用 Agent 已经能搜索和生成，社区不能只重复答案。它更有价值的是来自真实经验的社会验证，帮助用户判断一个做法在自己的处境中是否可用。
- 关联动作：
  - [已交付] 主链路：社区的目标不是展示更多 Agent，而是让 Agent 成为任务执行、关系连接与经验分发的协作节点；产品据此从面向 Agent，演进为人机协作和以人为中心的生产力社区。
  - [已交付] 专项：用世界杯与黑客松验证具体协作场景，由 Skill Finder 承接能力发现与增长，避免活动、增长与社区主线彼此割裂。
  - [已交付] 基础设施：围绕用户进入、内容消费、互动与留存建立指标、埋点和数据看板，并补齐安全合规与社区治理，让产品迭代有证据、有边界。
- 验证的工作方式：把复杂项目拆解并推进上线
- 结果结论：[已交付] 三阶段产品演进 · Agent 接入与 Skill 机制 · 用户交互与内容推荐
- 公开边界：公开结果覆盖已交付的主链路、业务专项与产品底座；专项指标仅说明专项期间的观察，不外推为 Meyo 整体表现或因果结论。

### 03 | 最强的 Skill，就一定最适合吗？
- 主题：评测与方法
- 关联项目：Skill 评测与召回决策系统
- 情境摘要：同一个问题会命中通用与专用 Skill；评测系统用场景相对增益建立可比较、可运行的选择依据。
- 公开判断：召回应比较增益，而不是只看谁更强。同一个问题常同时命中通用和专用 Skill。只看绝对分，通用 Skill 会长期占优；我更关心它在具体场景里相对基线提升了多少。
- 关联动作：
  - [已交付] 评测机制：将静态过滤、单 Skill 达标和同类横评组织成三层流程，一份执行 Trace 同时支持达标判断与横评。
  - [已交付] 系统落地：将评测标准沉淀为可重复运行的流程，已支持三层评测；下一步扩大场景覆盖，并验证对线上召回选择的实际改善。
- 验证的工作方式：先确认问题，再决定方案
- 结果结论：[已交付] 三层评测机制已运行 · 用场景相对增益选择 Skill · 一份 Trace 支持达标与横评
- 公开边界：三层评测系统与执行 Trace 复用已落地；场景增益覆盖度及其对线上召回收益的改善仍需持续验证。
